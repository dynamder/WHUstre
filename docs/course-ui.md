# 课程自定义界面与概念图谱

这份文档记录一次结构性改造的决策：给课程加自定义界面能力，并把工业互联网这门课的内容改由概念图谱组织。它同时记录被否掉的方案，避免下一轮重新讨论同一件事。

## 1 问题

三个问题叠在一起，前两个是内容问题，第三个是承载问题。

**内容按讲座组织，不按概念组织。** 课件 510 页，去重后只有 78 条定义、135 条重点、67 道题。同一批实体被反复讲：云计算在第二章出现 18 次、第五章 14 次；标识解析在第三章 20 次、第四章 31 次；现场总线横跨 5 章。后一章常常是前一章的细化，但课件不标注这层关系，读起来像重复。

**概念的范围与关系不清。** 同一个"架构"既指三体系又指三板块；"标识解析"既是整套设施又是一个动作；功能架构一会儿 4 层一会儿 3 体系；安全的"五"在不同章有三套名字。读者无法把概念组装成图。

**mdbook 只能线性阅读。** 它擅长目录、搜索、锚点、打印，不擅长关系型内容的来回导航。

## 2 目标与非目标

目标：

- 概念有唯一入口：一个概念一处定义、一组关系、一串题号。
- 关系可导航：从概念跳到关系、从关系跳到题、从题跳回概念。
- 不同课程能选不同的展示方式，互不牵连。
- 打印、无 JS、键盘操作仍然可用。

非目标：

- 不换掉 mdbook，不重做门面。
- 不建插件系统、不做通用数据管道、不抽象视图注册表。
- 不追求图形化炫技；图是索引，不是展示品。

## 3 内容决策

### 3.1 概念用超图组织

课件里真正让人卡住的关系都是三元的，两列表格装不下：

| 超边 | 结构 | 原型 |
| --- | --- | --- |
| 能力矩阵 | （层次, 体系）→ 能力 | 4 层 × 3 体系 |
| 安全矩阵 | （对象, 属性）→ 技术 | 五维度 × 五属性 |
| 选型 | （场景, 瓶颈, 指标）→ 技术 | 自动驾驶 / 时延 / 1 ms / uRLLC |
| 演进 | （版本, 要素, 变化）→ 结果 | 1.0 → 2.0 换平台 |
| 映射 | （体系, 系统）→ 对应 | 三体系 → 四系统 |
| 流程 | （阶段, 输入, 输出, 系统） | 采集 → 集成 → 建模 → 决策 |

二元边只需六类：`is-a`、`part-of`、`requires`、`refines`、`measures`、`contrasts`。

`refines` 是这门课特有的：第五章的云细化第二章的云，第四章的标识解析细化第三章的标识解析，第六章的安全细化第二章的风险。加上这条边，"重复"变成"分层"。

### 3.2 图谱与故事线分工

两者不冲突，各管一段：

- **故事线**：工厂里的实际情况与失败模式，回答"为什么需要它"。位置、人、一天怎么转、断链发生在哪。
- **图谱**：概念、关系、矩阵、题号，回答"它是什么、和谁有关、在哪一步用"。

规则：**机制只写在概念节点里，故事只写场景与失败模式。** 同一段机制不允许在两处各写一遍。

### 3.3 粒度：只收考试概念

纳入：能被单独考的名词、关系、指标、矩阵格。

剔除：

| 剔除项 | 理由 |
| --- | --- |
| 政策清单（2017—2026 一串文件） | 保留"国家顶层设计＋分阶段行动计划"一句 |
| 企业名单与案例数字 | 不构成概念 |
| 四次工业革命、工厂细节 | 保留"数字化—网络化—智能化"三阶段一个节点 |
| 价值宣示与政治表述 | 无信息量 |
| 纯名词堆叠页 | 名词已进节点 |

保留的例子只有两类：能承载机制的（震网说明物理隔离不等于安全），以及度量口径的（118 秒节拍、OEE 85% / 40–60%）。

### 3.4 概念关系就地澄清

不单开"概念地图"页。多义词、多套数字、同名不同物，在它第一次出现的地方给对照表，读者走到哪澄清到哪。

已按此处理的位置：第三章 §2.3（三个"三"）、§2.4（业务视图四层 vs 功能架构四层）、§2.5（网络体系 vs 物联网网络层）、§2.6（平台体系三层 vs 平台层）、§2.7（五属性 × 五对象）、§2.8（12 格矩阵）、§2.9（三体系 → 四系统）；第四章 §2.3（标识解析体系 vs 动作）、§2.4（三套"层"）；第五章 §2.2（平台功能架构 vs 体系功能架构）、§2.6（CPS 三层 vs 四层）、§2.7（两个"技术架构"）、§2.9（边缘层 vs 边缘计算）；第六章 §2.2（四套"五"）；第二章 §2.8（风险五类版本差异）。

### 3.5 写作约束

本轮已应用，后续沿用：

- 不用"不是 A，是 B"这类对举；直接给断言。
- 术语首次出现即展开缩写与含义。
- 清单必须带机制、量纲或代价，不复述课件。
- 工厂常识（现场、车间、产线、工单、节拍、换型）统一由第零章承担。

## 4 技术决策

### 4.1 保留 mdbook

mdbook 不适合画图，适合当"节点的落地页"：目录、搜索、锚点、打印都归它。图只占一个页面，其余页面不受影响。

不换 mdbook 的理由是仓库的跨课程一致性：门面是索引器、书是阅读器，两者只通过链接交接。换工具会推翻这条分工。

### 4.2 课程 UI 就是一个 Lustre 程序，不做框架

Lustre 本身是 MVU，缺的只是"怎么接进页面"这一条约定：

```html
<div id="graph-root"></div>
<script type="module" src="ui/graph.js"></script>
```

```gleam
pub fn mount(selector: String) {
  let app = lustre.simple(init, update, view)
  lustre.start(app, onto: selector, with: Nil)
}
```

没有视图注册表、没有 `data-view` 扫描、没有统一降级框架。多一个页面就多一个 `mount`，多一门课就多一个模块。

### 4.3 课程定义扩展

`meta.json` 增加可选字段，缺省即无自定义界面：

```json
"ui": [
  { "entry": "industrial-internet-graph", "out": "graph.js" },
  { "entry": "industrial-internet-quiz",  "out": "quiz.js" }
]
```

`gen-catalog.mjs` 已读 `meta.json`，加这个字段即可；`assemble.mjs` 按它把产物拷进 `dist/`。

### 4.4 数据写在 Gleam 里

不引入 JSON 数据文件与运行时解析：

```gleam
pub type Concept {
  Concept(id: String, name: String, cluster: Cluster, def: String, mechanism: String)
}
```

类型即校验：字段缺失或拼错，编译不过。引用完整性（超边指向不存在的概念）用一条普通测试兜住，不需要构建期校验层。

代价：改内容要重新编译，写内容的人写 Gleam。等真需要非程序员编辑数据时，再把这些常量挪成 JSON，不影响现有结构。

### 4.5 构建链

现有顺序：`gen-catalog` → mdbook（每课）→ `gleam build` → bundle → `assemble`。

新增一条：按课程定义循环打包 UI 入口。

```
gen-catalog          读 meta.json，产出 catalog.json
gleam build          编译门面与各课程 UI 模块
bundle               打门面 app.js；按 ui[] 打 courses/<slug>/ui/dist/*.js
mdbook build         生成 book/（图页只留挂载点与静态总表）
assemble             public/ + 各 book/ + 各 ui/dist/
```

两条硬约束：

1. **UI 产物不写进 `book/`**：mdbook 每次重建清空输出目录。产物落 `courses/<slug>/ui/dist/`，由 assemble 拷贝。
2. **脚本只在用到它的页面加载**：不用 `additional-js` 全局注入，避免每页都背 Cytoscape 的体积。

## 5 目录与产物

```
site/src/courses/industrial_internet/graph.gleam     概念图谱（MVU）
site/src/courses/industrial_internet/cyto_ffi.mjs    Cytoscape 桥接
site/scripts/entries/industrial-internet-graph.js    入口，调 mount
courses/industrial-internet/ui/dist/graph.js         构建产物（gitignore）
courses/industrial-internet/src/graph.md             mdbook 里的挂载页 + 静态总表
```

## 6 页面与交互

图谱页的目标是"复习时来回导航"，交互只做这几件：

| 动作 | 行为 |
| --- | --- |
| 点节点 | 侧栏出定义、机制、别名、题号、相邻超边 |
| 双击 | 只看邻居（ego network），再双击返回 |
| 搜索 | 规范名与别名模糊匹配，回车定位 |
| 簇过滤 | 六簇开关，关闭的簇折叠不消失 |
| 只看考过 | 按题号字段过滤 |
| 超边 | 矩阵型在侧栏渲染成小表，其余在图上用二分节点表示 |
| 键盘 | `/` 搜索、`j/k` 移动、`Enter` 进入、`Esc` 返回 |
| 定位 | 查询串 `?focus=<id>`，不用 hash（避开 mdbook 的锚点处理） |

## 7 降级

三件必做，按页面处理，不做通用层：

1. **打印**：canvas 打印空白。页面内附静态总表，`@media print` 隐藏画布、显示表格。
2. **无 JS**：同一张总表放 `<noscript>`。
3. **无障碍**：canvas 无可读语义。总表作为键盘与读屏入口，与图双向跳转。

## 8 风险

| 风险 | 应对 |
| --- | --- |
| 概念粒度失控（200+ 节点不可读） | 节点上限按"可单独考"定，约 90 个 |
| 故事与图谱各写一遍机制 | 机制只写节点，故事只写场景 |
| 课件自身的不一致被固化 | 节点带"口径"字段，冲突处注明版本 |
| mdbook 清空输出目录 | 产物落 ui/dist，assemble 负责拷贝 |
| 页面体积 | 图库只在图页加载 |
| 视图类型膨胀（若日后扩展） | 规则：表格加文字表达不了的，才新开视图 |

## 9 待定

1. 试点范围：先做工业互联网的图谱页，还是同时做互换性的一个表格页验证通用性。
2. 概念 ID 空间：`concept:tsn` / `question:4-10` 这类前缀是否统一。
3. 图谱数据先做哪一簇：建议网络簇，超边类型最全（矩阵、选型、映射、流程都有）。
4. 是否把图谱页放进 mdbook 目录，还是挂到门面作为独立入口。

## 10 已否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 单开"概念地图"页 | 概念关系应在出现处就地澄清，单独一页等于把问题挪走 |
| 换 Quartz / Astro / 自写 SPA | 推翻仓库"门面是索引器、书是阅读器"的分工，六门课不再同构 |
| 视图注册表 + JSON schema + 通用降级层 | 框架成本高于内容收益；Lustre 的 MVU 已经够用 |
| 每门课一个独立 Gleam 包 | CI 要为每包下载依赖；隔离靠模块命名即可 |
| 图谱页用 hash 路由 | mdbook 的 book.js 会接管 `#` 锚点，改用查询串 |

## 11 实现备注（本轮）

管线与骨架已落地：`meta.json` 的 `ui` 字段 → `catalog.json` → 按入口打包到
`courses/<slug>/ui/dist/` → assemble 拷到 `dist/courses/<slug>/ui/`。Gleam 侧是
`site/src/courses/industrial_internet/`（`concepts` 数据与查询、`graph` MVU、
`cyto` + `cyto_ffi.mjs` 画布边界），测试在 `site/test/concepts_test.gleam`。

与上文正文有出入、需要记录的三处：

1. **页面有两个挂载点**：`#graph-root` 归 Lustre，`#graph-canvas` 归 Cytoscape。
   MVU 每次更新会重画自己的子树，画布留在外面才不会被换掉；它仍是"一个页面一个
   mount"，不构成视图层。
2. **静态总表构建期生成**：`site/scripts/gen-graph-table.mjs` 调 Gleam 的
   `static_table()`，把片段写进 `src/graph-table.html`（gitignore），`graph.md` 用
   `{{#include}}` 引入。因此顺序改为 `gleam build` → `bundle` / 生成片段 →
   `mdbook build` → `assemble`，§4.5 的旧顺序作废。
3. **图页进 SUMMARY**：mdbook 只构建 `SUMMARY.md` 里的页面，所以新建了
   `# 图谱` Part（kind = `map`），门面显示为"图谱"标签。

§9 的待定项按本轮选择记录：只做工业互联网（不做互换性表格页）；概念 ID 用裸 id
（`tsn`、`he-network-system`），题号用"章-题"（`3-6` = 第三章课后习题第 6 题）。

### 11.1 第二轮：数据补齐（本轮）

占位数据换成了全课内容：六簇 98 个概念、85 条关系、67 道课后习题全覆盖（允许一题
挂多个概念，如 `3-6` 同时挂在网络互联、数据互通、标识解析下）。口径冲突不另设字段，
写在节点的 `caliber` 里（平台三层 vs 四层、顶级节点 5 城 vs 7 城、风险五类"管理" vs
"应用"、边缘层 vs 边缘计算）。两处与上文正文有出入，记录如下：

1. **超边多了一个 `cells` 字段**：`Cell(row, col, text)`。矩阵与选型型超边靠它落成真
   表格——12 格能力矩阵在侧栏与打印表里都是 4 行 × 3 列，不再是"两轴 + 一段说明"。
   行轴是设备层/工厂层/企业层/产业层四个概念节点，列轴是三大体系。
2. **`EdgeKind` 从 5 类扩到 11 类**：结构 5 类（矩阵、选型、演进、映射、流程）加二元
   6 类（上位、组成、依赖、细化、度量、对照）。二元边在画布上直接连成带箭头的线、
   不占菱形节点；`refines` 承载"第五章细化第二章的云、第六章细化第三章的五个维度"
   这层关系——加上它，课件里的"重复"才变成"分层"。第一轮 17 条结构超边让 54 个节点
   成了孤点，补完二元边后只剩两个：`internet-vs-web`（术语辨析）与 `stuxnet`（事件
   案例），由测试显式放行。

三处随之而来的实现细节：

- 侧栏的顺序是"角色清单 → 格子表"：表格的行列标签也是节点，点一下能跳过去。
- 静态表变成两张：概念表 98 行、关系总表 85 行（含每张矩阵的格子），关掉脚本与打印
  时信息不丢。
- 画布按 `binary` 字段分流：`hyperedge_json` 输出该布尔值，`build_elements` 据此决定
  画菱形还是画线。
