# 第三章 · 一张蓝图（体系架构）

> 对应课件第 3 章（P1–P30）。本章给出体系架构的两代版本（1.0 与 2.0）、三张功能视图（网络／平台／安全）与“4 层 × 3 体系”的功能架构。
>
> 读前先分清两组“三”：**三体系**（网络、平台、安全）是能力构成，回答“由什么组成”；**三板块**（业务视图、功能架构、实施框架）是设计方法，回答“怎么设计”。课件把两者都叫“架构”，混用从这一页开始。

## 1 场景：一个零件追不动

上一章攒了一地零件：感知、连通、云、大数据。现在把它们合起来用一次——把上个月的零件从头还原：哪台机床、哪个批次、哪把刀具、什么时候下的料。

第一步就卡住：名字对不上。

- 采集系统里这台机床叫 `Machine-07`，ERP 叫 `A07 加工中心`，客户台账叫 `X-3321`；
- 刀具更糟：MES 记 `T-88`，机床日志写“3 号刀位”。

三份记录拼不成一条线。48 小时追溯，连“这个零件是不是 Machine-07 做的”都赌咒不了。

问题出在*整体*：每块零件都是在自己的孤岛里搭起来的，没人规定过它们之间的接口。缺的是**一张图纸**——说清系统由哪几部分构成、各部件怎么协作、能力落在哪一层。

## 2 课件怎么说

### 2.1 体系架构 1.0（2016）：网络、数据、安全

1.0 的三根柱子：**网络**是工业系统互联和工业数据传输交换的**支撑基础**；**数据**是工业智能化的**核心驱动**；**安全**是网络与数据在工业中应用的**重要保障**（P5）。

三者对应三种功能：连（网络）、算（数据）、保（安全）。

1.0 还把应用侧拆成**三大优化闭环**（P6）：

| 闭环 | 数据来源 | 优化对象 | 产出 |
| --- | --- | --- | --- |
| 面向机器设备运行优化 | 机器操作数据、生产环境数据的实时感知 + 边缘计算 | 单台设备 | 智能机器、柔性生产线 |
| 面向生产运营优化 | 信息系统数据、MES 数据、控制系统数据的集成处理 + 大数据建模 | 工厂 | 动态优化调整的智能生产模式 |
| 面向企业协同、用户交互与产品服务优化 | 供应链数据、用户需求数据、产品服务数据 | 企业间 | 网络化协同、个性化定制、服务化延伸 |

三个闭环的划分依据是**优化对象的边界**：机器 → 产线 → 企业。这也解释了为什么后面的边缘计算、MES、供应链平台各管一段，不能互相替代。

### 2.2 从 1.0 到 2.0（2019）：为什么用“平台”换掉“数据”

2.0 的改动只有一处，但必须说清理由（P9）：

- **继承**：三大功能体系保留；
- **替换**：1.0 中“数据”与网络、安全在**数据功能上存在重叠**——网络负责传数据、安全负责护数据、数据自己又是核心，三者都绕着数据转，职责切不开。2.0 以**平台**替换**数据**，把“数据的集成、管理与建模分析”这摊活明确划给平台；
- **不变**：仍突出数据作为核心要素，仍强调数据智能化闭环的驱动作用。

一句话记：**2.0 换的是名字，把“数据”从体系名变成了平台体系内部的职责。**

### 2.3 2.0 的三大板块

体系架构 2.0 由**业务视图、功能架构、实施框架**三大板块构成（P10）。这三者是**设计方法**，与“网络、平台、安全”那三体系不在一个层面：三体系是设计出来的内容，三板块是设计它的步骤。形成一条自上而下的设计链：

```
商业目标与业务需求  →  系统功能定义  →  实施部署方式
   业务视图              功能架构          实施框架
```

至此，这一章出现了三个“三”，层面完全不同：

| 说法 | 层面 | 回答 | 内容 |
| --- | --- | --- | --- |
| 三大体系 | 内容 | 由什么组成 | 网络、平台、安全 |
| 三大板块 | 方法 | 怎么设计 | 业务视图 → 功能架构 → 实施框架 |
| 三张功能视图 | 展开 | 每个体系内部有什么 | 网络、平台、安全各自的功能视图 |

课件把前两个都叫“架构”：说“体系架构 1.0”时指三体系，说“体系架构 2.0”时指三板块。先认这一层，后面的层数与要素才对得上。

三个板块各回答一个问题（P11）：

| 板块 | 回答 | 明确的内容 |
| --- | --- | --- |
| 业务视图 | 干什么 | 企业应用工业互联网实现数字化转型的**目标、方向、业务场景及相应的数字化能力** |
| 功能架构 | 需要什么能力 | 支撑业务实现所需的**核心功能、基本原理和关键要素** |
| 实施框架 | 怎么落地 | 各项功能在企业落地实施的**层级结构、软硬件系统和部署方式** |

**业务视图的四个层次**（P13）：

- **产业层**：产业整体数字化转型的**宏观**视角（整个产业怎么转）；
- **商业层**：单个企业的业务与商业模式（微观）；
- **应用层**：落到哪些应用场景（微观）；
- **能力层**：这些场景需要哪些数字化能力（微观）。

只有产业层是宏观，其余三层都是企业视角。

这四层是**视角**（按决策主体分：产业、企业、场景、能力），与 §2.8 功能架构的四层（设备、工厂、企业、产业）不是一回事——那里是**责任范围**。两组里都有“产业层”，前者指站在产业整体看，后者指跨企业的骨干网与节点。

### 2.4 核心功能原理

全书只有这一句原理（P15）：

> 工业互联网的核心功能原理，是基于**数据驱动**的**物理系统**与**数字空间**的**全面互联与深度协同**，以及在此过程中的**智能分析与决策优化**。

拆开就是三步：给真实工厂建一个实时同步的数字影子（互联、协同）→ 在影子上分析（智能分析）→ 用结论把真实工厂调回去（决策优化）。这句是后面“数字孪生”“边云协同”的总纲。

### 2.5 网络功能视图：网络互联、数据互通、标识解析

网络体系由三部分组成（P16）：**网络互联**实现要素之间的数据传输；**数据互通**实现要素之间传输信息的相互理解；**标识解析**实现要素的标记、管理和定位。

顺序是**连 → 懂 → 找**，三者的关系是递进的：先有链路，才有语义，才有身份查询。

这里的“网络体系”与第二章物联网三层的“网络层”同名不同物：物联网三层按“采集—传输—处理”切，网络层只管传输；网络体系按“连—懂—找”切，除传输外还管语义互通与身份寻址，后两者在物联网三层里没有位置。

| 组成 | 定义 | 分层内容 |
| --- | --- | --- |
| 网络互联 | 通过有线、无线方式，将人、机、物、料、法、环全要素及企业上下游、智能产品、用户连接，支撑多要求数据转发，实现端到端数据传输（P17） | 多方式接入（有线：现场总线、工业以太网、工业 PON（Passive Optical Network，无源光网络）、TSN（Time-Sensitive Networking，时间敏感网络）；无线：5G/4G、WiFi6、WIA、WirelessHART、ISA100.11a（后三者为工业无线协议））→ 网络层转发（非实时/实时数据转发、网络控制、网络管理）→ 传输层传送（端口管理、端到端连接管理、安全管理） |
| 数据互通 | 实现数据和信息在各要素间、各系统间无缝传递，使异构系统在**数据层面**相互“理解”，实现数据互操作与信息集成（P18） | 应用层通信（OPC UA、MQTT、HTTP）→ 信息模型（OPC UA、MTConnect、YANG）→ 语义互操作（OPC UA、PLCopen、AutoML） |
| 标识解析 | 提供标识数据采集、标签管理、标识注册、标识解析、数据处理和标识数据建模（P19–20） | 见 §2.5.1 |

为什么“数据互通”要单独成一层：链路通了不等于对方听得懂。字段名、单位、量纲、采样含义不一致时，数据能到达但无法计算——这就是上一章“说得上话”的问题，靠统一信息模型解决。

表里那几个协议名各管一段：OPC UA（Open Platform Communications Unified Architecture，开放平台通信统一架构）既定义信息模型，也定义访问方式；MQTT（Message Queuing Telemetry Transport，消息队列遥测传输）是发布／订阅式的轻量传输协议；HTTP 是 Web 的传输协议，实时性最弱；MTConnect 面向机床数据；YANG 是 IETF 的数据建模语言；PLCopen 是围绕 IEC 61131-3 的 PLC 编程规范。

#### 2.5.1 标识解析的六个功能（P20）

| 功能 | 内容 |
| --- | --- |
| 标识数据采集 | 标识读写、数据传输；负责标识识读和数据预处理 |
| 标签管理 | 标识载体形式、标识编码存储形式；负责载体数据的存储、管理和控制 |
| 标识注册 | 在信息系统中创建对象标识注册数据并存储、管理、维护 |
| 标识解析 | 根据标识编码查询目标对象网络位置或相关信息，对机器和物品做唯一性定位和信息查询 |
| 标识数据处理 | 对采集后数据清洗、存储、检索、加工、变换、传输 |
| 标识数据建模 | 构建特定领域应用的标识数据服务模型，建立标识应用数据字典、知识图谱 |

六项按数据流排序：贴标（采集）→ 登记（注册）→ 查询（解析）→ 加工（处理）→ 建模（服务）。前两项在设备与应用侧，中间两项在解析网络里，后两项回到应用侧。

### 2.6 平台功能视图

按功能层级，平台分三层（P21）：

| 层 | 功能 |
| --- | --- |
| 边缘层 | 海量工业数据接入、转换、数据预处理、边缘分析应用 |
| PaaS 层 | 资源管理、工业数据与模型管理、工业建模分析、工业应用创新 |
| 应用层 | 工业创新应用、开发者社区、应用商店、应用二次开发集成 |

三层的划分依据是**离设备的距离**：边缘层处理“来不及上传、也不该上传”的数据；PaaS 层做复用（一次建模，多次调用）；应用层面向具体业务。

注意“平台层”的两种用法：平台体系的三层是边缘层／PaaS 层／应用层；§2.8 功能架构四层里的“平台层”指 PaaS 那一段，与边缘层、应用层并列。同一个词，一处指体系，一处指体系里的一层。

### 2.7 安全功能视图

工业互联网安全体系考虑**五大安全**（P23）：**可靠性、保密性、完整性、可用性、隐私和数据保护**。这五个是**属性**：保护到什么程度。

另一组五个是**对象**：设备、控制、网络、应用、数据。保护谁。

两组正交相乘，就是安全体系架构（P27）那张图：横轴五个对象，纵轴五个属性，交叉格里填具体技术。

| 对象 | 这一列主要防什么 |
| --- | --- |
| 设备 | 固件被改、漏洞未补、硬件被替换 |
| 控制 | 控制指令被伪造、控制逻辑被篡改 |
| 网络 | 边界被穿透、流量被劫持、可用性被打掉 |
| 应用 | 平台与 App 的漏洞、越权访问 |
| 数据 | 传输与存储被窃取、敏感字段未脱敏 |

每个对象的防护技术清单在第六章逐条展开；本节只需要记住“属性 × 对象”这个乘法关系。

对比互联网经典的 CIA 三要素（保密性 Confidentiality、完整性 Integrity、可用性 Availability），多了两个，多的这两个正是“工业”的分水岭：

- **可靠性**：工业系统不能宕机。CIA 只保证“用得到”，不保证“不中断”；
- **隐私和数据保护**：工业数据里既有工艺参数（商业机密），也有员工与用户信息。

### 2.8 功能架构：4 层 × 3 体系

把三张功能视图摞起来，纵向切成四个层次，得到功能架构（P24–25）。这张图是**乘法表**：横轴 3 个体系、纵轴 4 个层次，交叉格是“某层需要的某类能力”。

| 层次 | 代表要素（P25 原图） | 该层网络要求 |
| --- | --- | --- |
| 产业层 | 国家或集团骨干网络、专线网络、运营商网络、IPv4/IPv6 | 低时延、高可靠、大带宽 |
| 企业层 | 企业与园区网络、云平台服务、云边协同设施、公有云／私有云 | 高可靠、全覆盖、大带宽 |
| 工厂层 | 生产控制网络、边缘设备接入、工业数据采集、控制信息传输；SCADA/DCS、PLC/CNC | 高可靠、高安全、高融合 |
| 设备层 | 智能机器、专用设备、成套设备、仪器仪表；工业总线／工业以太网／TSN／蜂窝模块、RTU、边缘网关 | 现场总线、工业以太网、TSN、无线接入 |

四点层次对应的物理范围与典型系统见第零章 §7。两点容易记错：MES（制造执行系统）、ERP（企业资源计划）、PLM（产品生命周期管理）、CAX（CAD/CAE/CAPP 的统称）、WMS（仓储管理）、SCM（供应链管理）、PHM（故障预测与健康管理）等信息系统在企业层，不属于设备层；“4 层”讲的是**责任范围**（单机→工厂→企业→产业），与设备实际放在哪无关。

纵向的责任划分：每一层都要同时实现网络、平台、安全三类能力，只是侧重不同。这就是“4 层 × 3 体系”的用法——任何项目都能在矩阵里定位自己缺哪一格。

把 12 格填满，这张图就完整了：

| 层次 ＼ 体系 | 网络 | 平台 | 安全 |
| --- | --- | --- | --- |
| 产业层 | 国家或集团骨干网、运营商网络、专线 | 跨企业平台、标识解析顶级与二级节点、行业云 | 行业监管、威胁情报共享、跨企业身份互认 |
| 企业层 | 园区网、云专线、SD-WAN | 企业云平台、ERP／PLM、数据中台 | 企业身份与权限、审计、边界防护 |
| 工厂层 | 生产控制网、边缘接入、工业以太网 | MES／SCADA、边缘计算平台 | 工控边界（工业防火墙）、入侵检测、网络隔离 |
| 设备层 | 现场总线、工业以太网、TSN、无线模组 | 边缘网关、设备侧嵌入式软件、智能传感器 | 固件安全、硬件信任根、安全芯片 |

填格的意义在于区分同名不同物：设备层的“平台”是边缘网关，企业层的“平台”是 ERP 云平台，两者都在平台这一列，内容完全不同。

### 2.9 实施框架：四大实施系统

落地阶段只剩四个可立项的系统（P29）：**网络系统、标识系统、平台系统、安全系统**。

落地的是“标识系统”：到施工图阶段，标识解析被单拎出来作为一个工程，因为它是“名字对不上”这个问题的根，必须独立建设、独立验收。

四个系统与三体系不是一一对应：

| 体系 | 落成的系统 |
| --- | --- |
| 网络体系 | 网络系统 ＋ **标识系统**（标识解析从网络体系里拆出来单独立项） |
| 平台体系 | 平台系统 |
| 安全体系 | 安全系统 |

所以“3 体系”变成“4 系统”，多出来的就是标识。

## 6 课后习题（课件 P30 原题）

<summary>参考答案</summary>

**1. 请阐述工业互联网的体系架构 1.0，并简单画出其架构图。**
1.0（2016）以网络、数据、安全为三大核心：网络是工业系统互联和工业数据传输交换的支撑基础；数据是工业智能化的核心驱动；安全是网络与数据在工业中应用的重要保障。架构图自上而下分三层：顶层为应用侧三大优化闭环（面向机器设备运行优化、面向生产运营优化、面向企业协同与用户交互及产品服务优化）；中层为数据（采集、集成、建模分析）与网络（互联、互通）；底层为安全，纵向贯穿三层。

架构图可用文字框图表示：横向写网络／数据／安全三列，纵向写设备—工厂—企业三层。

**2. 体系架构 2.0 包括哪三大板块？各明确了什么？**
业务视图、功能架构、实施框架。业务视图明确企业应用工业互联网实现数字化转型的目标、方向、业务场景及相应数字化能力；功能架构明确支撑业务实现所需的核心功能、基本原理和关键要素；实施框架描述各项功能在企业落地实施的层级结构、软硬件系统和部署方式。三者构成“商业目标与业务需求 → 系统功能定义 → 实施部署方式”的设计链。

**3. 业务视图包括哪四个层次？各明确什么？**
①产业层：产业整体数字化转型的宏观视角，明确产业整体转型方向；②商业层：单个企业的业务与商业模式，明确企业业务目标与商业模式创新；③应用层：落到具体应用场景，明确场景清单；④能力层：明确支撑这些场景所需的数字化能力。产业层是宏观，其余三层是企业微观视角。

**4. 工业互联网核心功能原理是什么？**
基于数据驱动的物理系统与数字空间全面互联与深度协同，以及在此过程中的智能分析与决策优化。即：为物理工厂建立实时同步的数字空间，实现双向互联与协同，在数字空间完成智能分析与优化决策，再反馈回物理系统。

**5. 网络体系由哪三部分组成？各有什么作用？**
网络互联、数据互通、标识解析。网络互联实现要素之间的数据传输（连）；数据互通实现要素之间传输信息的相互理解（懂）；标识解析实现要素的标记、管理和定位（找）。三者递进：先有链路，才有语义，才有身份查询。

**6. 什么是网络互联、数据互通、标识解析？各提供/包括哪些功能？**
网络互联：通过有线、无线方式连接人、机、物、料、法、环全要素及上下游、智能产品、用户，支撑多要求数据转发，包括多方式接入（现场总线、工业以太网、工业 PON、TSN；5G/4G、WiFi6、WIA、WirelessHART、ISA100.11a）、网络层转发（实时与非实时数据转发、网络控制、网络管理）、传输层传送（端口管理、端到端连接管理、安全管理）。
数据互通：使异构系统在数据层面相互理解，实现数据互操作与信息集成；包括应用层通信（OPC UA、MQTT、HTTP）、信息模型（OPC UA、MTConnect、YANG）、语义互操作（OPC UA、PLCopen、AutoML）。
标识解析：提供标识数据采集、标签管理、标识注册、标识解析、数据处理、标识数据建模六项功能，实现要素的标记、管理和定位。

**7. 平台体系由哪三部分组成？各有什么作用？**
边缘层：海量工业数据接入、转换、数据预处理和边缘分析应用，解决“来不及上传、也不该上传”的数据；PaaS 层：资源管理、工业数据与模型管理、工业建模分析、工业应用创新，解决模型复用；应用层：工业创新应用、开发者社区、应用商店、应用二次开发集成，面向具体业务交付。

**8. 安全体系主要包括哪 5 个维度？**
设备安全、控制安全、网络安全、应用安全、数据安全。这一组是安全体系架构（P27）的横向维度划分，按对象切分。与之配套的是“五大安全”属性：可靠性、保密性、完整性、可用性、隐私和数据保护。两组都以“5”出现，但指两件事：维度按保护对象切分，属性按保护目标切分。

**9. 安全体系框架主要包括哪几大重点？**
五大安全属性（可靠性、保密性、完整性、可用性、隐私和数据保护）与五个维度（设备、控制、网络、应用、数据）。框架沿两个方向展开：属性定义“保护到什么程度”，维度定义“保护谁”；每一格再落到具体技术，如设备侧的固件攻击面减少、漏洞修复与补丁管理、硬件安全增强；网络侧的隔离、边界管控、入侵检测、接入管理；数据侧的加密、脱敏、使用授权、存储加密；并引入人工智能、区块链、可信计算、零信任等新兴技术。
