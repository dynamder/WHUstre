# 第六章 · 一面盾牌（安全技术）

> 对应课件第 6 章（P1–P77）。本章按“威胁—框架—五个维度—五类防护—区块链”展开，主线是五个维度各自“变了什么、因此带来什么挑战”。

## 1 场景：一条穿过墙壁的蠕虫

警报来自同行。一家厂的产线被锁死，每台停机的机床都是“非计划停机”，按合同每小时 5000 元。

在这之前还有一个更老的案子。**震网病毒（Stuxnet，又称超级工厂病毒）**：**首个**专门针对工业控制系统的破坏性蠕虫，也是全球第一个主动攻击真实世界基础设施的蠕虫。它攻击伊朗纳坦兹核工厂的西门子工控系统，使铀浓缩离心机大规模故障。

攻击路径六步（P7）：

| 步 | 动作 |
| --- | --- |
| 1 感染 | 通过介质与终端进入目标网络 |
| 2 扫描 | 探测目标型号、拓扑与控制系统版本 |
| 3 更新 | 自我更新，维持存活与变种能力 |
| 4 破坏 | 篡改执行机构动作，让离心机超速 |
| 5 控制 | 接管控制逻辑，可远程、可重复触发 |
| 6 欺骗、摧毁 | **伪造监控读数**，操作员看到的仍是正常曲线 |

第六步是分水岭：破坏发生在物理层，人机界面没有告警。这就是工业安全与信息安全的差别——**后果不止数据泄露，还包括设备损坏、停产、人身伤害**。

而且它穿过了“气隙”（air gap，物理上不与互联网连通的内网）：那套系统根本没接互联网。物理隔离只切断网络路径，不消除**介质入口**——维护笔记本、移动存储、厂商远程升级都能把代码带过去。**物理隔离不等于安全**（P10）。

## 2 课件怎么说

### 2.1 五类威胁：串联成链

**五类安全威胁**（P11）：设备安全、控制安全、网络安全、应用安全、数据安全。其中终端设备安全、生产控制系统安全、数据安全尤为急迫。

这五项与第三章的“五个安全维度”是同一组对象，只换了视角：那里说“保护谁”，这里说“攻击从哪进”。

课件里一共出现四套“五”，容易串味：

| 出处 | 名称 | 内容 | 回答 |
| --- | --- | --- | --- |
| 第二章 P89 | 风险五类 | 设备、网络、数据、控制、管理 | 风险从哪来 |
| 第三章 P23 | 五大属性 | 可靠性、保密性、完整性、可用性、隐私和数据保护 | 保护到什么程度 |
| 第三章 P27 | 五个维度 | 设备、控制、网络、应用、数据 | 保护谁 |
| 本章 P11 | 五类威胁 | 设备、控制、网络、应用、数据 | 攻击从哪进 |

第三与第四条是同一组对象换视角；第二条与它们正交相乘，才是安全体系架构那张图。

关键在于它们**按控制流与数据流串成一条链**。任一层被突破，攻击者都能用该层的权限向相邻层横向移动（横向移动：以已攻破的一层为跳板，向相邻层渗透）：入口通常在网络层或应用层（IT 侧），后果落在控制层与设备层（OT 侧）。课件把这条路径概括为“**攻击从 IT 层渗透到 OT 层**”。

### 2.2 安全框架：五层 + 四类新兴技术

**工业互联网安全框架**（P13）以设备、控制、网络、应用、数据五个层次组织防护技术，另设人工智能、区块链、可信计算、零信任等新兴技术支撑层。这五层就是第三章的五个安全维度（保护对象），换了个说法；“层”在这里指防护对象的层次，与功能架构里的“层”无关。P13 那一整页是技术名词堆叠，没有解释，机制在后续各节。

### 2.3 五个维度各自发生了什么变化

每一维都是“变了什么 → 因此带来什么挑战”两步，课件给的是成对对偶（P15–P27）。

| 维度 | 变了什么 | 因此带来什么挑战 |
| --- | --- | --- |
| 设备 | 由机械结构变为 **EOS（Embedded Operating System，嵌入式操作系统）＋微处理器＋应用软件**，可编程、可联网、可远程更新，攻击面从物理操作转向代码执行 | 漏洞影响从特定型号设备扩散到海量通用设备（同类设备共用同一固件，一个漏洞批量命中）；攻击路径从控制系统直达智能设备，中间那层隔离消失 |
| 控制 | 生产控制由**分层、封闭、局部**变为**扁平、开放、全局**；控制环境由封闭走向 IT 与 OT 融合；控制布局变为**控制监测上移、实时控制下移** | **OT 层不再可信**——OT 侧的控制协议与软件普遍缺认证与加密机制，攻击者用通用 IT 手段即可直达控制逻辑；**信息安全与功能安全交织**，攻击可绕过安全逻辑直接造成物理伤害 |
| 网络 | 协议由专有、不公开转向以太网/IP，公开且工具链通用；网络由静态转动态 | 攻击代码可复用，门槛极大降低；**工业以太网交换机性能低，易受 DDoS**——现场交换机以实时性与成本为设计目标，缓存与控制面处理能力弱 |
| 应用 | 多用户、多设备、多平台、多工序，数据来源多、类型多，跨组织、跨区域 | 身份与权限边界跨企业，无法用单一安全域的策略覆盖；不同业务的安全需求不同，隔离能力与业务保障能力要求同时抬高 |
| 数据 | 由**少量、单一、单向**变为**大量、多维、双向**，工厂内外网络双向流动共享 | 泄露点随流转节点数量增长；数据体量增大、种类增多、结构复杂，使分类分级与脱敏难以覆盖全量 |

“扁平化”在这里指中间管理层级被压缩、决策权下移到生产一线；在控制系统里，它对应的是原本靠层级隔离形成的缓冲带被挤压。应用侧覆盖**智能化生产、网络化协同、个性化定制、服务化延伸**四类模式（P23）；**ICS（Industrial Control Systems，工业控制系统）**主要包括 SCADA、DCS、PLC 及其它控制系统（P17），是被攻击的那类对象的总称。**DDoS（Distributed Denial of Service，分布式拒绝服务）**：通过大量受控设备向目标系统发送海量请求，使其无法为正常用户提供服务。

### 2.4 设备安全

对象是工业机器人、智能仪表、传感器等现场智能设备（P14）。五项防护：

| 技术 | 内容 |
| --- | --- |
| **FASR**（Firmware Attack Surface Reduction，固件攻击面减少） | 从操作系统内核、协议栈层面做安全增强，阻止恶意代码传播与运行（P29） |
| 漏洞修复 | 修复设备中已存在的漏洞和安全弱点（P30） |
| 补丁管理 | 补丁的**检测、下载、测试、批准、安装**全过程（P30） |
| 运维管控 | 对外部存储器等硬件连接设备的使用进行管控，部署运维管控系统、对硬件进行标识（P31） |
| 硬件安全增强 | 把**硬件级部件（安全芯片或安全固件）作为系统信任根**，并对硬件进行标识（P31） |

三个机制点。**固件是攻击面**（P29）：固件是存储在硬件设备中、直接控制底层操作、充当硬件与高级软件之间桥梁的特殊软件，恶意代码植入后上层软件察觉不到，重装系统也清不掉，所以防护点要前移到内核与协议栈，直接削减可被利用的入口。**补丁不能“打上就行”**（P30）：工控设备不允许随意停机，补丁必须先在测试环境验证兼容性，经批准后才安装并持续监测，测试与批准这两个环节是可用性与安全性之间的强制折中。**硬件信任根**：软件层的完整性校验自身可被篡改；以安全芯片或安全固件为起点逐级向上度量启动链，才能在“系统可能已被攻破”的前提下判定可信。

### 2.5 控制安全

对象是控制软件与控制协议（P14）。

| 技术 | 内容 | 机制 |
| --- | --- | --- |
| 身份认证 | 知识类、资产类、本征类三类组合（P33） | 单一因子可被窃取、复制或伪造；OT 协议本身不带身份字段，只能在协议之上补认证，以确保控制命令来自合法用户 |
| 白名单 | 建立工业控制协议白名单访问控制策略，过滤非法访问，只允许白名单内的可信任指令和消息传输（P33） | 工控指令集固定、种类有限，可完整枚举正常行为；“只放行已知合法”能挡住未知攻击与变种，代价是设备或工况变更时须同步维护策略 |
| 访问控制 | 鉴别身份后，准许或限制用户对数据信息的访问能力及范围（P34） | 认证只回答“你是谁”，访问控制回答“你能做什么”；认证通过不等于有权操作全部资源 |
| 传输加密 | 三条途径：协议栈增加安全层、应用数据单元增加安全字段、改进通信会话过程（P35） | 专有协议没有预留加密字段，只能“改造”；三种改法都要付出时延与兼容性代价，实时回路多选轻量方案 |
| 脆弱性测试 | 系统化识别系统、网络、应用中的安全弱点，量化分析威胁并给出修复建议（P36） | 漏洞管理与风险管理的核心环节 |
| 软件防篡改 | 代码测试、完整性校验、代码加密（P38） | 防止攻击者篡改工业控制软件 |
| 恶意软件防护 | 恶意代码的检测、预防和恢复（P39） |  |
| 安全监测与审计 | 利用工业软件操作的**周期性**，测量协议不同阶段执行中的偏差；利用控制软件中的**时间序列**信息，以无监督学习做异常检测（P41） | 工控攻击样本稀缺、无法提供标注数据，所以用无监督 |

**模糊测试（Fuzzing）**（P36–37）：脆弱性测试的主要手段，占 **80%**；按测试者对目标内部信息的掌握程度分**黑盒、白盒、灰盒**三类。它占主导的原因是：工控协议实现普遍缺少健壮性设计，畸形输入即可触发崩溃或越界，而模糊测试不需要源码，可直接对运行态协议栈施压。

### 2.6 网络安全

对象是工厂内部网络、外部网络及两者边界（P14）。

| 技术 | 内容 | 判据／机制 |
| --- | --- | --- |
| 网络隔离 | **物理隔离、协议隔离、应用隔离**（P43） | 隔离强度与成本依次递减、可用性依次递增；典型场景为内外网隔离、生产网与办公网隔离、工控系统隔离 |
| 边界管控 | 在边界部署安全防御设备，监视安全域边界，识别并阻断入侵行为（P44） | 把无限的内网流量收敛到有限检查点，使入侵识别具备可实施的位置 |
| 接入管理 | 对接入的设备与**标识解析节点**进行身份认证，保证合法接入和合法连接（P45） | 在连接建立前验证身份，把非法连接挡在建立阶段；标识解析节点被伪造可劫持寻址 |
| 通信和传输保护 | 加密技术、校验机制（P46） | 保护网络层通信与传输过程 |
| 入侵检测 | 基于**规则库**比对已知恶意序列；基于**异常**建立正常基线，用机器学习、当前用深度学习（P47） | 规则库准确率高但对未知攻击无效；异常检测能发现未知行为但误报率高，深度学习是为了压低误报 |
| DDoS 防御 | 负载均衡、内容分发网络（CDN）、分布式集群防御（P50） | 把流量分散到多个入口与节点，避免单点被耗尽 |

### 2.7 应用安全：两大类

**平台安全**（P49）：安全审计（谁在何时改了什么）、认证授权（身份与权限）、安全隔离（租户与业务之间不串）、安全监测（异常行为）、补丁升级（平台自身漏洞）、DDoS 防御（可用性）。

**工业应用程序安全**（P49）：代码审计（源码缺陷）、脆弱性检测（黑盒找洞）、审核测试（上线前评审）、补丁升级（已发布版本的漏洞）、行为监测和异常阻止（运行态拦截）。

四个易混点的判据都是“看什么、有没有源码”：

| 技术 | 白盒／黑盒 | 内容 |
| --- | --- | --- |
| 代码审计 | 白盒，需源码 | 检查源代码中的缺点和错误，找出可能引发的安全漏洞（P51） |
| 脆弱性检测 | 黑盒，针对已发布程序 | 基于漏洞数据库或 APP 逆向，对工业应用程序做漏洞发现（P52） |
| 行为监测及异常阻止 | 运行态 | 基于静态行为规则匹配或机器学习识别并阻断异常行为（P53） |
| 审核测试 | 流程 | 上线前评审与测试，属流程性控制 |

### 2.8 数据安全：按三阶段切

| 阶段 | 手段（P55） |
| --- | --- |
| 传输 | 加密 |
| 处理 | 敏感性识别、使用授权、脱敏 |
| 存储 | 访问控制、存储加密 |

**脱敏与加密的区别**：脱敏是处理阶段对敏感字段变形，使数据可用但不可还原到个体；加密是传输与存储阶段用密钥保护，授权者仍可还原。判据是**是否保留可还原性**。

三类新兴技术补上数据侧的三块短板：

| 技术 | 补什么 | 机制 |
| --- | --- | --- |
| **可信计算**（P58） | 平台完整性 | 硬件与软件协同，确保设备、数据、应用程序按预期安全运行；从硬件信任根逐级度量启动链，证明“当前运行的东西没被改” |
| **零信任**（P59） | “内网即可信”这个假设 | 不默认任何位置可信，每次访问都重新验证；把权限判定从“位置”改为“身份＋上下文” |
| **区块链**（P57、P61） | 存证的可信性 | 见 §2.9 |

另有基于人工智能的四项数据安全能力（P56），各对应一个环节：智能识别保护（自动发现敏感字段并打标）、智能安全溯源（数据被谁、何时、从哪条路径取走，可回溯）、智能风险预警（从访问行为里识别异常模式，提前告警）、智能精准管控（按数据分级与使用者上下文动态放行或阻断）。共同点是**从人工定规则转向用行为数据定规则**。

### 2.9 区块链

**区块链**：由区块（block）组成的链式数据结构，是去中心化的、不可篡改的分布式账本技术，通过链式结构记录交易和信息以实现数据透明与安全（P61）。

**四个特点**（P63），每个都能落到机制：

| 特点 | 机制 |
| --- | --- |
| 透明性 | 账本对参与方公开，任何人可复核历史记录 |
| 不可篡改 | 每块含前块哈希，改一处则后续全部失效，需掌握多数节点算力才能重写 |
| 去中心化 | 无中心账本，消除单点信任与单点篡改 |
| 可追溯性 | 链式结构保留全部历史，可逐笔回溯 |

**不可篡改的机制**：每个区块含前一区块的哈希，改动任一历史区块会使后续所有区块哈希失效，须重算全部后继区块并掌握多数节点算力才可能被接受；去掉中心账本则消除了单点信任与单点篡改。代价同样明确：写入慢（要共识）、存储冗余（每节点存全量）、隐私需额外设计（账本公开）。所以它适合多主体、低频、需存证的场合，不适合高频实时数据。

**工业区块链的技术基础**（P64），四件各管一件事：

| 技术 | 管什么 | 缺了会怎样 |
| --- | --- | --- |
| 数字签名 | 写入者身份与防抵赖 | 谁写的说不清，出问题无法定责 |
| 时间戳 | 给每条记录定序 | 可以事后补录，前后顺序不可信 |
| 分布式共识与多方存储 | 多方各存一份，单方改不动 | 回到“信任某个管理员”的老问题 |
| 智能合约自动执行 | 规则上链，条件满足即执行 | 仍要人工核对，效率与公信力都打折 |

**功能特色**（P64）是这四件的组合效果：**多中心化信任构建**（不必另找第三方背书）、**跨组织高效协作**（共享一本账代替互相核对）、**可控安全共享**（按权限看）、**可追溯审计防篡改**（历史记录改不动）。

**四大难题与四个方案**（P65–P76）：

| 难题 | 方案 |
| --- | --- |
| 多平台多设备缺统一可信身份，信任构建难 | **联盟数字身份**：基于区块链分布式账本，按场景签发多个联盟身份 ID 与凭证，支持身份自生成、自存储、自销毁的全生命周期管理（P66–68） |
| 数据权属与责任不清，确权流转难 | 资产标签上链、链上链下绑定、隔离通道加流转共识的访问控制 |
| 原始数据不愿共享且计算过程不透明，安全共享难 | 多方密文同态计算（密文上直接计算，解密后与明文计算结果一致，做到“数据可用不可见”），加留痕与激励 |
| 跨组织缺统一追溯，事件审计追溯难 | 事件可信共享渠道、区块链上事件映射逻辑链、**智能合约**自主执行——把事件行为簇以时间为单位打包成审计报告（P76） |

**智能合约**：部署在链上、条件满足即自动执行的程序代码。它解决的是“审计报告要人工整理、结论可被质疑”的问题：条件与规则写进代码，执行过程与结果都可核。

**区块链存证与数据库审计的分界**：区块链把哈希写进多方共维的链，改一条要改全网多数副本，可信性来自共识；数据库审计依赖日志，日志由管理员掌控、可被删改，可信性来自制度与权限。判据是**谁能单方面改写记录**。

## 4 核心定义

| 名词 | 定义 |
| --- | --- |
| 震网病毒（Stuxnet） | 首个专门针对工业控制系统的破坏性蠕虫，攻击伊朗纳坦兹核工厂的西门子工控系统，使铀浓缩离心机大规模故障；全球第一个主动攻击真实世界基础设施的蠕虫 |

| ICS（工业控制系统） | 主要包括 SCADA 系统、DCS、PLC 及其它控制系统，是被攻击的主要对象 |
| EOS（嵌入式操作系统） | 智能设备的新型构成模式为 EOS＋微处理器＋应用软件，是设备由机械化转向智能化的技术标志 |
| 固件 | 存储在硬件设备中、直接控制设备底层操作、充当硬件与高级软件之间桥梁的特殊软件 |
| FASR（固件攻击面减少） | 从操作系统内核、协议栈层面做安全增强，阻止恶意代码传播与运行 |
| 补丁管理 | 补丁的检测、下载、测试、批准和安装全过程，是可用性与安全性之间的折中 |
| 系统信任根 | 以硬件级部件（安全芯片或安全固件）作为系统信任的起点，逐级向上度量启动链 |
| 白名单技术 | 建立工业控制协议白名单访问控制策略，过滤非法访问，只允许白名单内的可信任指令和消息传输 |
| 访问控制 | 鉴别访问主体合法身份后，通过某种途径准许或限制用户对数据信息的访问能力及范围 |
| 脆弱性测试 | 系统化识别系统、网络、应用中安全弱点的检测方法，量化分析潜在威胁并提出修复建议，是漏洞管理与风险管理的核心环节 |
| 模糊测试（Fuzzing） | 脆弱性测试的主要手段（占 80%），按测试者对目标内部信息的掌握程度分黑盒、白盒、灰盒三类 |
| 网络隔离 | 限制网络之间的资源共享以防止信息泄露，含物理隔离、协议隔离、应用隔离 |
| 边界管控 | 在网络边界部署安全防御设备，监视安全域边界，识别入侵行为并阻断 |
| 接入管理 | 对接入设备与标识解析节点进行身份认证，保证合法接入和合法连接 |
| 入侵检测系统 | 通过对网络流量的分析实现流量监测与告警，技术路线分基于规则库与基于异常两类 |
| DDoS 攻击 | 通过大量受控设备向目标系统发送海量请求，使其无法为正常用户提供服务 |
| 可信计算 | 通过硬件和软件协同，确保计算设备、数据和应用程序在任何情况下都能按预期安全运行的技术体系 |
| 零信任架构 | 不默认任何位置（含内网）可信，每次访问都需重新验证，用于数据可信访问 |
| 区块链 | 由区块组成的链式数据结构，是去中心化的、不可篡改的分布式账本；特点为透明性、不可篡改性、去中心化、可追溯性 |
| 智能合约 | 部署在链上、条件满足即自动执行的程序代码，用于把审计规则固化为可自动核验的执行逻辑 |
| 联盟数字身份 | 基于区块链分布式账本，按场景签发多个联盟身份 ID 与凭证的人机物实体身份表示方法，支持身份自生成、自存储、自销毁 |

**1. 简述震网病毒事件的基本情况及其对工业互联网安全的警示意义。**
基本情况：震网（Stuxnet，超级工厂病毒）是首个专门针对工业控制系统的破坏性蠕虫，也是全球第一个主动攻击真实世界基础设施的蠕虫；它攻击伊朗纳坦兹核工厂的西门子工控系统，使铀浓缩离心机大规模故障，伊朗核工业陷入停滞。攻击路径六步：感染、扫描、更新、破坏、控制、欺骗与摧毁。
警示意义：①**网络攻击可以对现实世界的工业设备造成物理破坏**，后果不止数据泄露，还包括设备损坏、停产与人身伤害；②**物理隔离不等于安全**——它穿过气隙进入内网，说明“没有连接就没有攻击面”的假设不成立，介质入口都是通道；③单一防护措施极易被突破，安全机制薄弱时攻击可长期潜伏；④第六步“欺骗”说明监控读数不可信，必须具备独立于控制系统的审计与校验能力；⑤信息安全与功能安全交织，责任横跨 IT 与生产安全两个部门。

**2. 主要安全威胁有哪五类？各自核心关注点及内在逻辑关系？**
五类：设备安全（现场智能设备的固件、漏洞与运维口）、控制安全（控制软件与控制协议缺认证、缺加密）、网络安全（内网、外网及边界的隔离、边界管控、接入与流量）、应用安全（平台与工业应用程序的漏洞与行为）、数据安全（数据在传输、处理、存储三阶段的泄露与篡改）。核心关注点分别是：设备能否被改写、控制命令能否被伪造、边界能否被穿透、应用能否被利用、数据能否被窃取或篡改。
内在逻辑：五者按控制流与数据流**串联**成一条链。攻击入口通常在 IT 侧（网络、应用），后果落在 OT 侧（控制、设备、数据）。任一层被突破后，攻击者可用该层权限向相邻层横向移动，因此防护必须逐层设卡，任一层失守都会使其余层暴露。

**3. 简述工业互联网安全框架的层次结构及各层主要防护内容。**
框架按设备、控制、网络、应用、数据五个层次组织，另设人工智能、区块链、可信计算、零信任等新兴技术支撑层。各层内容：设备安全——固件攻击面减少、漏洞修复与补丁管理、硬件安全增强（信任根、硬件标识）、运维管控；控制安全——控制协议的身份认证（知识类／资产类／本征类）、白名单、访问控制、传输加密、脆弱性测试、控制软件的防篡改、恶意软件防护、安全监测与审计；网络安全——网络隔离（物理／协议／应用）、边界管控、接入管理、通信和传输保护、入侵检测、DDoS 防御；应用安全——平台安全（审计、认证授权、隔离、监测、补丁、DDoS 防御）与工业应用程序安全（代码审计、补丁升级、脆弱性检测、审核测试、行为监测与异常阻止）；数据安全——传输加密、处理阶段的敏感性识别与脱敏与使用授权、存储阶段的访问控制与存储加密。

**4. “设备、控制、网络、应用、数据”五个维度各自发生了怎样的变化？带来哪些新挑战？**
设备：由机械结构变为 EOS＋微处理器＋应用软件，具备可编程、可联网、可远程更新能力，攻击面从物理操作扩展到代码执行；挑战是漏洞影响从特定型号扩散到海量通用设备（同固件批量命中），攻击可从控制系统直达智能设备。
控制：生产控制由分层、封闭、局部变为扁平、开放、全局，IT 与 OT 融合，控制监测上移、实时控制下移；挑战是 OT 层不再可信，控制协议与软件缺认证加密，攻击者可用通用 IT 手段直达控制逻辑，且信息安全与功能安全交织。
网络：协议由专有转向以太网/IP，网络由静态转动态；挑战是协议公开、工具链通用、攻击代码可复用，门槛大降；工业以太网交换机性能低，易受 DDoS，短时拥塞即等价控制失效。
应用：多用户、多设备、多平台、多工序，数据来源与类型多，跨组织、跨区域；挑战是身份与权限边界跨企业，无法用单一安全域策略覆盖，隔离能力与业务保障能力要求同时抬高。
数据：由少量、单一、单向变为大量、多维、双向，工厂内外双向流动共享；挑战是泄露点随流转节点增长，体量与异构度使分类分级与脱敏难以覆盖全量。

**5. 五个维度各自的主要防护技术。**
设备：FASR（内核与协议栈层面增强）、漏洞修复、补丁管理（检测—下载—测试—批准—安装）、运维管控（外部存储器与硬件连接管控、硬件标识）、硬件安全增强（安全芯片或安全固件作系统信任根）。
控制：身份认证（知识类＋资产类＋本征类组合）、协议白名单、访问控制、传输加密（协议栈安全层／应用数据单元安全字段／改进会话过程）、脆弱性测试与模糊测试、软件防篡改（代码测试、完整性校验、代码加密）、恶意软件防护、安全监测与审计（利用操作周期性与时间序列、无监督学习）。
网络：网络隔离（物理／协议／应用）、边界管控、接入管理（设备与标识解析节点身份认证）、通信和传输保护（加密、校验）、入侵检测（规则库与异常两条路线，现多用深度学习）、DDoS 防御（负载均衡、CDN、分布式集群防御）。
应用：平台安全（安全审计、认证授权、安全隔离、安全监测、补丁升级、DDoS 防御）与应用程序安全（代码审计、补丁升级、脆弱性检测、审核测试、行为监测和异常阻止）。
数据：传输加密；处理的敏感性识别、使用授权、脱敏；存储的访问控制与存储加密；并以可信计算、零信任、区块链、人工智能等新兴技术补强平台完整性、访问可信性与存证可信性。

**6. 工业应用安全防护有哪两大类？各包含哪些主要技术？**
两大类：平台安全与工业应用程序安全。平台安全含安全审计、认证授权、安全隔离、安全监测、补丁升级、DDoS 防御；工业应用程序安全含代码审计（白盒查源码）、补丁升级、脆弱性检测（黑盒，基于漏洞库或 APP 逆向）、审核测试（上线前评审与测试）、行为监测和异常阻止（静态行为规则匹配或机器学习）。判据：代码审计看源码，脆弱性检测看已发布程序，行为监测看运行态。

**7. 什么是区块链？具有哪些特性？**
区块链是由区块组成的链式数据结构，是去中心化的、不可篡改的分布式账本技术，通过链式结构记录交易和信息以实现数据透明与安全。技术基础包括数字签名、时间戳、分布式共识及多方存储、智能合约自动执行。四个特性：透明性、不可篡改性、去中心化、可追溯性，可减少交易成本和时间。不可篡改来自链式哈希：每个区块含前一区块哈希，改动任一历史区块会使后续全部失效，须重算后继并掌握多数节点算力才可能被接受；去中心化则消除了单点信任与单点篡改。

**8. 工业区块链解决了工业互联网安全中的哪些核心难题？举例说明。**
四大难题对应四个方案：①**信任构建难**（多平台、多设备缺统一可信身份）——联盟数字身份：基于分布式账本按场景签发多个联盟身份 ID 与凭证，身份自生成、自存储、自销毁，实现人机物实体的全生命周期身份管理；②**数据确权流转难**（权属与责任不清）——资产标签上链、链上链下绑定、隔离通道加流转共识的访问控制，使流转路径与责任人可核；③**数据安全共享难**（原始数据不愿共享、计算过程不透明）——多方密文同态计算加留痕与激励，做到“数据可用不可见”；④**事件审计追溯难**（跨组织缺统一追溯）——建立事件可信共享渠道与链上事件映射逻辑链，配合智能合约自主执行，把事件行为簇以时间为单位打包成审计报告，实现审计数据的自动化标注与更新。
举例：三家供应商与主机厂共同追溯一批零件的质量问题时，各方原始工艺数据不出门，只上链哈希与结论；一旦发生批量缺陷，可沿链上逻辑链定位到具体批次、设备与操作记录，且任何一方无法事后修改该记录。

## 7 收尾：一个目的

盾立起来之后，第一次没有哪里着火。可以回答第一章那张表了：

| 条款 | 现在怎么答 |
| --- | --- |
| 联网率 ≥90% | 感知层与网络层（第二、四章） |
| 48 小时追溯 | 标识解析 ＋ 平台的数据集成（第三、四、五章） |
| 4 小时响应 | 状态可观测 ＋ 边缘告警（第一、五章） |
| OEE 协商一致 | 数据可信 ＋ 安全审计（本章） |

再看一遍这门课的全部零件，它们只在回答三个问题：**数据从哪来**（感知与网络）、**数据变成什么**（平台与模型）、**凭什么让人相信**（标识、安全、审计）。

第三问才是这门课的门槛。技术都能买到，能被第三方复核的数据买不到——而正是“能被第三方复核”这一条，让机床从一次性买卖变成可以按年收费的服务。

这就是工业互联网的目的：**把一锤子买卖变成持续的订阅，把设备商变成服务商**。所有低时延、高可靠、标识解析、数字孪生、区块链存证，最后都指向同一张纸——客户愿意签字的那张报表。
