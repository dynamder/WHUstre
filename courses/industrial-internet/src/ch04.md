# 第四章 · 一条主线（网络关键技术）

> 对应课件第 4 章（P1–P82）。本章给数据三样东西：身份（标识与解析）、通道（工厂内网与工厂外网）、时间（TSN 与边缘计算）。

## 1 场景：贴纸不会回话

图纸说“标识解析”。我们真做一次：给车间每台设备、每把刀具、每个在制品贴二维码。扫码能查到出厂日期、采购单号。第一个月很顺。

然后客户打来电话：这把刀**什么时候装上的、装在哪台机床上、加工了多少件**？

贴纸答不出来。它是**被动载体**：没电、不说话，只有人拿扫描枪扫它时才吐出固化在里面的编码。设备换到另一个车间，贴纸还是那张贴纸，它不知道自己去过哪。

更麻烦的是标识本身：出厂时厂家给的编号、客户台账的编号、我们自己 ERP 的编号，三者互不相干。同一个零件，三家三套号。

两件事同时发生：**标识要能自己上报**，**编号要有一套全网认的规则**。

## 2 课件怎么说

### 2.1 标识：给对象一个终身不变的号

**工业互联网标识**：一种标识化系统，通过数字化、编码或其他形式的唯一识别符号，为工业物品、设备、产品等实体赋予独特标识符号，使其在互联网环境中被唯一识别、定位和管理（P6、P14）。

**为什么不用 IP 地址当标识**：IP 给“接口／位置”编号，随接入网段变化；标识给“对象／身份”编号，终身不变（P5–6）。两者分离后，同一台设备换厂区、换网段，仍能被同一个标识引用。

标识编码按段分配，例如 `86.10000/ac.qd.1024`，段位是**国家—厂商/设备—城市—序列号**（P6）。分段的用处是：各主体只在自己那一段内编号，避免全局冲突；上级只需按段前缀转发，解析不必查全表。

**标识的三个作用**（P12）：唯一识别物理实体和数字实体、支撑网络互联互通、支撑数据共享共用。

**推广标识解析体系的五条原因**（P18）：①工厂内设备标识复杂；②企业内数据交流困难；③企业间信息互通困难；④国家内统一布局缺乏；⑤国际上数据安全受威胁。

### 2.2 载体：被动与主动

| 类型 | 形态 | 能力 | 代价 |
| --- | --- | --- | --- |
| **被动标识载体** | 条形码、二维码、RFID、NFC（P8） | 无供电、无通信，只能被外部读取 | 成本可压到极低、寿命等同印刷；但只存固化编码，读不出运行状态 |
| **主动标识载体** | UICC（Universal Integrated Circuit Card，通用集成电路卡）、MCU（Microcontroller Unit，微控制器）、通信模组、终端（P9） | 自带供电与通信，可主动联网上报 | 供电、成本、维护；换来实时状态与自报位置 |

选型判据只有一条：**是否需要实时状态**。要追“这把刀装在哪台机床上”，被动载体就交不了差。

课件在 P8–P9 只提问未作答。答案：被动载体难在**唯一性与防复制**（贴纸可撕、可仿），主动载体难在**供电与安全**（联网即攻击面）。

**标识安全体系**（P11）分两面：**标识安全性**（编码不被伪造、载体不被复制）与**标识隐私保护**（编码不泄露物品与持有人信息）。四个手段各治一段：

| 手段 | 治什么 |
| --- | --- |
| 加密编码 | 编码可被任何人扫到，加密后无法反推对象信息 |
| 加密传输 | 解析请求与响应在链路上不被窃听篡改 |
| 数据匿名访问控制 | 查询者只拿到授权字段 |
| 标识生命周期管理 | 载体回收、注销、重发，防止旧标签被冒用 |

难点在载体侧：被动标签（二维码、RFID）没有算力，自己无法加密，只能靠读取端与后台补。

### 2.3 标识解析：把名字翻译成地址

**标识解析**：对标识编码进行解析，实现信息查询和定位，进而支撑**跨企业、跨行业、跨地域**的数据互通和精准协同（P17）。

这里“标识解析”是动作与功能。整套设施叫“标识解析体系”，包含四部分：

```
标识解析体系
├─ 标识编码   怎么编号（国家—厂商／设备—城市—序列号）
├─ 标识载体   贴什么（条形码、二维码、RFID、NFC；UICC、模组、终端）
├─ 解析节点   谁来回话（国际根 → 国家顶级 → 二级 → 企业，另有递归节点）
└─ 标识解析   按编码查到地址与信息（动作与功能）
```

体系里还有一个“标识解析”，是层级包含而非重复：外层指设施，内层指动作。看到“标识解析体系”“解析节点”，说的是设施；看到“解析一次”“解析服务”，说的是动作。

**核心内容两部分**（P17，填空）：**标识编码** ＋ **标识解析**。编码解决“怎么编号、谁分配”，解析解决“怎么查到”。

**系统组成**（P17、P20）：解析发起方、解析节点、数据服务器。流程是发起方提交标识 → 解析节点逐级寻址 → 找到该标识所关联对象的地址 → 返回信息对象。

**为什么分层**：对象数据分散在成千上万家企业且各自更新，全网维护单一映射表既不可扩展，也无数据主权。分层之后上级只存“下一跳在哪”，对象数据留在企业节点——**编码统一，数据分散**。

**解析体系的层级**（P20、P22）：

```
国际根节点（对接 Handle 根系统 MPA，平等、协商、共管）
   ↓
国家顶级节点（国内顶层）        ← 公共递归节点（代理查询并缓存）
   ↓
二级节点（面向行业／区域的汇聚节点）
   ↓
企业节点（存放本企业对象数据）
```

注册层级是四层；课件把查询侧的公共递归节点也算进来，称为“五层”。两种口径都在用，区别在于递归节点不参与编码分配，只负责查：

四个节点的分工：

| 节点 | 职责 |
| --- | --- |
| 国家顶级节点 | 国内标识解析体系的顶层节点，对接国际根节点，管理全国标识编码与解析服务 |
| 二级节点 | 面向行业或区域的汇聚节点，位于顶级与企业之间，是标识解析集成创新应用的主要抓手 |
| 企业节点 | 企业内部标识解析信息系统对应节点，存放本企业对象数据 |
| 公共递归节点 | 代理发起方完成多级查询并缓存结果；避免每次解析都从根逐级查，降低根节点负载与响应时延 |

**递归节点为什么必要**：热点标识被反复查询，若每次都从根走一遍，根节点会成为瓶颈。缓存让第二次查询直接命中。

**四套根节点体系**（P20）：Handle（由多主根共管的标识解析体系）、OID/GS1（对象标识符与全球商品编码体系）、DID（Decentralized Identifier，去中心化标识）、DNS（Domain Name System，域名系统）。中国接入 Handle 体系的方式是成为 MPA（Handle 根系统的多主根管理机构）下的 **GHR（国际并联根节点）**，其下还有 **ARS（全球辅根节点）**、ARS-MPA、**LHS（下级授权节点）**。

> 页码口径差异：第 1 章 P61 记国家顶级节点 5 地（北京、上海、重庆、广州、武汉），本章 P20 列 7 地（另加南京、成都）。正文按“北京、上海、重庆、广州、武汉”记，并注明“另有南京、成都等地节点在建”；引用页码时以所用章节为准。

### 2.4 工厂内网络：两层三级

**工厂内网络**：实现工厂内部人的互联、物的互联、机的互联，支撑厂内业务应用（P29），结构是**两层三级**（P33）。三级与车间的空间结构一一对应：现场级是设备旁，车间级是一个车间，工厂级是整个厂（第零章 §1、§7）。

全书一共出现三套“层”，彼此不是同一把尺子：

| 出处 | 切法 | 层级 |
| --- | --- | --- |
| 第零章 §1 | 物理空间 | 厂区 → 车间 → 工段 → 产线 → 工位 |
| 本章 §2.4 | 网络归属 | 现场级、车间级、工厂级（两层：IT／OT） |
| 第三章 §2.8 | 责任范围 | 设备、工厂、企业、产业（4 层 × 3 体系） |

对得上的是“现场级≈设备层、车间级与工厂级≈工厂层、企业级≈企业层”；产业层在三层两级的结构里没有对应，它跨出了单个工厂。

| | 层级 | 归属 | 承载 |
| --- | --- | --- | --- |
| 两层 | IT 网络（信息技术网络） | 工厂级／企业级 | ERP、MES、办公、数据中心 |
| | OT 网络（运营技术网络） | 车间级 ＋ 现场级 | SCADA/HMI（车间级；HMI＝Human-Machine Interface，人机界面）、PLC/DCS 与传感器执行器（现场级） |

**IT 与 OT 的主要区别**：

| 维度 | IT | OT |
| --- | --- | --- |
| 目标 | 吞吐、通用协议、频繁升级 | 周期确定、可用性、长生命周期 |
| 实时性 | 尽力而为 | 硬实时（现场级毫秒级闭环） |
| 故障后果 | 业务中断、数据丢失 | 停产、设备损坏、人身风险 |
| 更新窗口 | 随时 | 检修窗口，不能随便打补丁 |

所以两者必须隔离：办公网的拥塞与病毒不能进控制回路。OT 内部再分车间级与现场级，也是同一个逻辑——**不同实时性预算配不同成本的技术**。

**工厂内网按业务纵向切分**（P39–P41）为四张网：生产网、办公网、安防网、企业数据中心。生产网内部再分三类业务：**控制类、采集类、连接类**。切分的目的是能分别设 QoS（Quality of Service，服务质量）与安全策略，避免互相抢占。

工厂内骨干是**多技术并存**的（P32、P37）：固定高实时设备走工业以太网／TSN；移动设备（AGV（Automated Guided Vehicle，自动导引车）、手持终端、移动面板）只能无线；布线困难区域用蜂窝。网络控制器把数据流与控制流分开调度。

### 2.5 工厂外网络：三专线一连接

**工厂外网络**：连接智能工厂、分支机构、上下游协作企业、工业云数据中心、智能产品与用户等主体（P30），由**三个专线加一个连接**构成（P43）。

四种业务的分类依据是**对端是谁**：

| 业务 | 对端 | 核心需求 | 承载 |
| --- | --- | --- | --- |
| ①上网专线 | 公网 | 访问互联网资源 | IP、Ethernet、ATM、SDH/SONET |
| ②互联专线 | 异地厂区、分支机构 | 端到端隔离与可预期时延 | MPLS VPN、基于 OTN 的光网专线、SD-WAN |
| ③上云专线 | 工业云数据中心 | 大带宽、低成本入云 | Cloud VPN（入云总线） |
| ④上网连接 | 出厂产品、移动作业 | 移动性与广覆盖 | LTE、NB-IoT、5G |

**两种专线的分工**（P44）：

- **MPLS VPN**：用 MPLS（Multiprotocol Label Switching，多协议标记交换）在共享承载网上切出逻辑隔离的 VPN（Virtual Private Network，虚拟专用网），按需开通、成本低；但转发仍受拥塞影响。
- **OTN（Optical Transport Network，光传送网）**：分三层——光通信层 OCH、光复用段层 OMS、光传输段层 OTS；在光层给独享波长／子波长（硬管道），带宽大、抖动小，适合承载生产控制。

实践分工：**MPLS 做灵活互联，OTN 做重载骨干**。

**SDN 与 SD-WAN**（P45）：广域网多链路（DSL／Fiber／LTE）逐台配置、静态选路，无法按应用调度。SDN（Software-Defined Networking，软件定义网络）把控制平面从设备抽到集中控制器；SD-WAN 是这套架构在企业广域网上的落地——控制器统一编排多链路、按业务选路、叠加加密，用低价链路承载高价值业务。

**Cloud VPN（云网融合网络框架）**（P46）：以“入云总线”把企业本地数据中心、办公网、总部与分支机构同工业云数据中心互联。

“入云总线”是一个汇聚点：企业各处的网络先接到总线上，再由总线统一连到云。省的是专线数量与配置工作量，代价是总线本身成为单点，必须做冗余。

### 2.6 三种协议族

**有线分两大体系：现场总线与工业以太网**（P37），以现场控制为主。

| 族 | 协议（课件列出） | 特征 |
| --- | --- | --- |
| 现场总线（8 个，P51） | ControlNet、AS-I、CANopen、Modbus、InterBus、CC-Link、DeviceNet、Profibus | 数字化、双向、多节点；低速、小数据量、周期性 I/O |
| 工业以太网（4 个，P54） | Modbus TCP、EtherNet/IP、Ethernet CAT、Profinet | 用 IEEE 802.3 帧、交换式、带宽高 |
| 工业无线（8 个，P57） | 6LoWPAN、ZigBee、LoRa、Bluetooth/LE、ISA100.11a、WirelessHART、WIA-PA/FA、WLAN | 补布线死角与移动设备 |

现场总线的确定性来自**共享介质上的受控访问**：单介质多节点，用主从轮询或令牌把发送权在固定周期内分给各站，扫描周期可预期；代价是带宽低。
工业以太网要进现场必须加固：标准以太网 CSMA/CD 冲突后随机退避重传，时延不可界；用交换式全双工消除冲突、划分实时通道、按优先级排队，把“尽力而为”改成“可预期”。

**异构协议怎么互通**（P60，简答三条）：①中间件和网关设备；②协议适配器和转换器软件；③协议数据格式转换。原理是先把各协议报文解析成统一数据模型，再上行——多协议共存的最低成本解，代价是网关本身成为单点与延迟来源。

### 2.7 TSN：给以太网加上时间表

**TSN（时间敏感网络）**：由 IEEE **802.1** 制定的一组以太网增强标准，在标准以太网上实现**确定性通信**，确保关键数据在严格时间限制内以**低延迟、低抖动、高可靠性**传输（P65）。

**它针对传统工业以太网的四个问题**（P64，填空原题）：实时性差、数据抖动、传输碰撞、资源竞争。

**核心原理**（P66）：**全局时钟 ＋ 传输调度器**。

- 全局时钟：全网设备用同一时间基准同步（IEEE 802.1AS）；
- 传输调度器：交换机按时间表（门控，IEEE 802.1Qbv）在指定时隙只放行指定流，关键流不和背景流量争抢队列；
- 结果：最坏时延与抖动**可计算**；再叠加冗余路径与帧复制消除（802.1CB），把丢包率压到极低。

一句话区分：传统工业以太网靠**优先级**排队，拥塞时不可界；TSN 靠**时间片**预约，拥塞也不影响。

### 2.8 边缘计算与边云协同

**边缘计算**：在靠近物或数据源头的网络边缘侧，融合网络、计算、存储、应用核心能力的分布式开放平台，就近提供边缘智能服务（P69）。

**存在的理由**：云中心到现场的往返时延与回传带宽，撑不住毫秒级闭环和海量视频；把计算下沉，能缩短链路、减少上行流量，并在与云断连时本地继续运行。

**两个视图的区别**（P71、P75）：

| 视图 | 回答 | 内容 |
| --- | --- | --- |
| 功能视图 | 做什么 | 边缘侧提供**自动化控制、分析、优化**三类功能，由边缘管理器做业务编排与资源调用；分层为现场设备—边缘端—云端 |
| 能力视图 | 靠什么做 | **计算、网络、存储**三类基础能力 |

**边云协同**（P79、P81）：边缘算力与存储有限、只见局部数据；云端有全量历史数据与大算力，适合训练与长周期分析。于是分工是**云端训练、边缘推理与实时控制**，形成“模型下发—数据上送”的闭环。课件给出的规模口径：六种主要业务形态、六大主场景、十四种子场景。

**5G 进入工业的支点**（P62–63）：有线覆盖不了移动设备，WiFi 的切换与干扰不可控；5G 用大带宽、毫秒级空口时延与网络切片在公网上切出隔离逻辑网，配合边缘计算把用户面下沉到工厂侧，避免回传绕行。

| 5G 指标（P63） | 数值 |
| --- | --- |
| 广连接 | 100 万／km² |
| 大带宽 | 1 Gbit/s |
| 低时延 | 1 ms |
| 高可靠 | 99.9999% |
| 微抖动 | 1 μs |

这五个数各有口径，不能直接比较：

- **1 ms** 是空口单向用户面时延（uRLLC 目标值），不含跨地域回传；跨 1000 km 往返再加 10 ms 传播时延。
- **99.9999%** 是可靠性，即丢包率 10⁻⁵，靠冗余与重传实现，与“时延 1 ms”是互相拉扯的：重传提高可靠性，但延长时延。
- **1 μs** 是抖动（相邻包时延之差）；控制回路约束的是抖动。
- **100 万/km²** 是连接密度，指同一时刻可服务的连接数，与终端是否休眠无关（见第二章 §2.5.3）。
- **1 Gbit/s** 是峰值速率；单用户实际速率取决于调度与负载。

三大使能技术：高频和多天线（要带宽）、网络切片（要隔离）、边缘计算（要短回传）。

**1. 简述工业互联网标识的定义及其主要作用。**
定义：通过数字化、编码或其他形式的唯一识别符号，为工业物品、设备、产品等实体赋予独特标识，使其在互联网环境中被唯一识别、定位和管理的标识化系统。作用三条：唯一识别物理实体和数字实体；支撑网络互联互通；支撑数据共享共用（P12）。它与 IP 的分工是：IP 编号位置、随网段变化，标识编号身份、终身不变。

**2. 主动与被动标识载体各举两例，简述优缺点。**
被动载体：二维码、RFID（另有条形码、NFC）。优点：无供电、成本极低、寿命等同印刷、无维护；缺点：只能被外部读取，只存固化编码，读不出运行状态，且可撕可仿，唯一性与防复制难保证。主动载体：UICC、通信模组（另有 MCU、终端）。优点：自带供电与通信，可主动联网上报状态与位置，支撑实时监控；缺点：需供电、成本与维护投入高，且联网即扩大攻击面，须配套认证与加密。

**3. 简述工业互联网标识解析的定义及其核心作用。**
定义：对标识编码进行解析，实现信息查询和定位，进而支撑跨企业、跨行业、跨地域的数据互通和精准协同。核心作用：把“名字”翻译成“地址与信息”，使同一对象在不同系统、不同企业、不同地域之间能被一致地引用与查询；没有解析，标识只能被读、不能被定位。

**4. 标识解析体系分哪五个层级？简述层级关系与各自功能。**
五层为：国际根节点、国家顶级节点、二级节点、企业节点、公共递归节点。层级关系：①国际根节点——处在最顶层，对接 Handle 根系统 MPA，全球各根系统之间“平等、协商、共管”，中国以 GHR（国际并联根节点）接入；②国家顶级节点——国内体系的顶层，管理全国标识编码与解析服务，向下连接二级节点；③二级节点——面向行业或区域的汇聚节点，上连顶级、下接企业，是标识解析集成创新应用的主要抓手；④企业节点——企业内部标识解析信息系统对应节点，存放本企业对象数据；⑤公共递归节点——不在注册层级上，而是挂在解析服务侧的查询代理，代理发起方一次完成多级查询并缓存结果，降低根节点负载与查询时延。解析过程：发起方提交标识 → 递归节点查缓存或逐级寻址 → 命中企业节点数据服务器 → 返回该标识所关联对象的信息。

**5. 工厂内网和工厂外网分别解决什么问题？**
工厂内网解决工厂内部人、物、机的互联与厂内业务应用支撑，结构为“两层三级”（IT／OT 两层，工厂级、车间级、现场级三级），按业务切成生产网、办公网、安防网、企业数据中心。工厂外网解决工厂与外部主体（异地厂区、分支机构、上下游企业、工业云数据中心、出厂产品与用户）的连接，由上网专线、互联专线、上云专线加一个上网连接构成，判据是“对端是谁”。

**6. 简述“两层三级”，并说明 IT 与 OT 的主要区别。**
两层：工厂 IT 网络与工厂 OT 网络；三级：工厂级（企业级）、车间级、现场级。IT 网络覆盖工厂级与企业级，承载 ERP、MES、办公、数据中心，追求吞吐与通用性、可频繁升级；OT 网络覆盖车间级与现场级，承载 SCADA/HMI、PLC/DCS、传感器与执行器，要求周期确定、硬实时、长生命周期与不停机。区别的关键在故障后果：IT 故障是业务中断，OT 故障是停产、设备损坏甚至人身风险，因此两者必须隔离，且更新只能在检修窗口进行。

**7. 简述工厂外网络的四种业务及其核心需求。**
①上网专线：对端是公网，需求是访问互联网资源；②互联专线：对端是异地厂区与分支机构，需求是端到端隔离与可预期时延，承载用 MPLS VPN、OTN 光网专线、SD-WAN；③上云专线：对端是工业云数据中心，需求是大带宽、低成本入云，用 Cloud VPN（入云总线）；④上网连接：对端是出厂产品与移动作业，需求是移动性与广覆盖，用 LTE、NB-IoT、5G。分类依据是通信对端与承载要求。

**8. 简述现场总线协议与工业以太网协议的主要区别，各举两例。**
区别：介质访问与带宽。现场总线是低速总线／串行链路，多节点共享介质，靠主从轮询或令牌获得确定性，适合小数据量周期性 I/O；工业以太网使用 IEEE 802.3 帧、交换式全双工，带宽高，靠实时通道、优先级或时间调度获得确定性。举例：现场总线——Profibus、Modbus（另 ControlNet、CANopen、DeviceNet、CC-Link、AS-I、InterBus）；工业以太网——Profinet、EtherNet/IP（另 Modbus TCP、Ethernet CAT）。

**9. 现场存在多种异构工业协议，如何保证通信高速有效？列举几种方案。**
①中间件和网关设备：把 Profinet、EtherNet/IP、Modbus、无线协议的报文解析成统一数据模型后上行；②协议适配器和转换器软件：在控制器或边缘侧做协议翻译与地址映射；③协议数据格式转换：统一数据字典与量纲，解决语义不一致。方案选择的判据是实时性要求与改动成本：网关改造最小但引入单点与额外延迟，边缘侧适配可保留原控制回路不动；统一到 OPC UA 类信息模型则一次性解决语义问题，但需设备侧支持。

**10. 什么是 TSN？它解决了传统工业以太网的哪些问题？核心原理是什么？**
TSN 是由 IEEE 802.1 制定的一组以太网增强标准，在标准以太网上实现确定性通信，确保关键数据在严格时间限制内以低延迟、低抖动、高可靠传输。它针对传统工业以太网的四个问题：实时性差、数据抖动、传输碰撞、资源竞争。核心原理是“全局时钟＋传输调度器”：全网设备用同一时间基准同步（802.1AS），交换机按时间表门控（802.1Qbv）在指定时隙只放行指定流，关键流不与背景流量争抢队列，最坏时延与抖动因此可计算；再叠加冗余路径与帧复制消除（802.1CB）降低丢包。

**11. 简述边缘计算的定义、主要功能，及其与云计算的关系。**
定义：在靠近物或数据源头的网络边缘侧，融合网络、计算、存储、应用核心能力的分布式开放平台，就近提供边缘智能服务。主要功能（功能视图）：自动化控制、分析、优化三类，由边缘管理器做业务编排与资源调用；能力上以计算、网络、存储三类基础能力刻画。与云的关系是协同：边缘算力与存储有限、只见局部数据，负责毫秒级实时控制与推理，断网可自治；云端有全量历史数据与大算力，负责模型训练与长周期全局分析。二者形成“模型下发—数据上送”的闭环，即边云协同。

## 7 本章在叙事里的位置

网络这一段给出了三样东西：**身份**（标识与解析，回答“这是谁”）、**通道**（两层三级与三专线一连接，回答“怎么走”）、**时间**（TSN 与边缘计算，回答“来不来得及”）。三样凑齐，数据才第一次成为可交付的原料。但原料离产品还差一段加工——把它变成客户肯签字的东西，是下一章的事。
